# 카드 디펜스 — 컴퓨터 그래픽스 최종 프로젝트 제안서

## 1. 프로젝트 개요

### 팀 소개

| 이름 | 반 | 역할 |
|---|---|---|
| 이현수 | 1반 | 그래픽스: 카메라·마우스 선택, 툰 렌더링, VFX(파티클·셰이더 효과), UI·팩 개봉 연출, 피규어 모델 |
| 최명준 | 1반 | 게임 로직: 라운드·타이머, 몹 이동, 공격, 칩·팩·손패, 화면 전환 |

면담·발표 반: 1반

### 제목, 장르, 규모

- **제목**: 카드 디펜스 — "카드를 내려놓으면, 말이 튀어나와 판을 지킨다"
- **장르**: 1인용 카드 타워 디펜스

| 항목 | 내용 |
|---|---|
| 스테이지 | 보드게임 판 1개: 네모 순환 길 + 안쪽 4×4 칸. 10라운드(라운드당 30초), 10라운드는 보스. 수치는 데이터 파일(CSV)로 조정 |
| 캐릭터(말) | 3클래스 × 3등급 = 9종. 마법사(범위·약함), 궁수(균형), 전사(단일·강함) |
| 적 | 4종: 해골 병사, 고블린, 오크, 보스 그림자 왕 |
| 카드·아이템 | 필수: 유닛 카드 9종, 부스터 팩 / 권장: 운석 주사위, 유물 / 선택: 주문 2종, 승격 카드, 골드 부스터 |
| 배경 | 작업대 위 보드게임 판, 치비 미니어처 디오라마 (팔레트: 풀 #91B86D, 나무 #BC9067, 카드 #FFF0CF, 강조 #70AADC) |

### 게임의 목적과 핵심 아이디어

- **배경**: 카드 속 보드게임 세계. 카드를 판에 놓으면 카드가 타들어 사라지고 피규어 말이 떨어져 칸에 놓인다.
- **목표**: 10라운드를 버티고 보스를 처치한다. 라운드마다 30초 안에 몹을 모두 잡지 못하면 패배.
- **핵심 순환**: 몹 처치 → 칩 → 팩 구매 → 카드 → 말 배치 → 다시 몹 처치

| 주요 규칙 | 내용 |
|---|---|
| 정비 | 몹을 다 잡으면 시간이 멈춘다. 카드 사용·팩 구매 후 턴 종료로 다음 라운드 |
| 전투 | 몹은 15초 동안 등장해 길을 계속 돈다. 말은 사거리 안의 몹을 자동 공격 |
| 판 | 바깥 12칸은 사거리가 짧은 말도 닿고, 가운데 4칸은 사거리가 긴 높은 등급만 닿는다 |
| 손패·팩 | 손패 최대 6장, 팩 1개 = 카드 1장. 손패가 차면 살 수 없다 |
| 유닛 카드 | 빈 칸에 놓으면 말 등장, 차 있으면 기존 말과 교체 |
| 권장 규칙 | 칩 베팅(몹을 늘리고 클리어하면 유물), 운석 주사위(범위 피해 × 주사위 눈), 말 옮기기 |

**차별점**

1. **팩 개봉이 곧 전략**: 무작위 카드를 16칸·6장 손패 안에서 배치한다.
2. **3D 보드게임 세계**: 피규어가 떨어져 놓이고, 몬스터 말이 체스말처럼 한 칸씩 뛰어 전진한다.
3. **모든 사건에 셰이더 연출**: 직접 만든 파티클 시스템과 디졸브 셰이더를 소환·피격·처치·팩 개봉에 재사용한다.
4. **툰 렌더링**: 계단 명암과 외곽선으로 손으로 칠한 미니어처처럼 보이게 한다.

### 게임 진행 방법

| 입력 | 동작 |
|---|---|
| 왼쪽 드래그 / 클릭 | 카드를 판에 끌어 놓기 / 팩 구매, 턴 종료 |
| 오른쪽 드래그 / 휠 | 카메라 회전 / 줌 |
| F1~F4 | 데모 키: 다음 라운드, 칩 추가, 보스 라운드, 이펙트 다시 재생 |

- **시작**: 타이틀은 게임과 같은 화면이고 패에 Start·Exit 카드가 있다. Start 카드를 판에 놓으면 시작해, 기본 조작을 자연스럽게 익힌다.
- **진행**: 정비 → 턴 종료 → 전투 30초 → 정비 … 10라운드까지
- **종료**: 보스 처치 시 승리, 시간 초과 시 패배. 결과 화면의 패에 Retry·Title 카드. 타이틀에서 Exit 카드를 놓으면 종료.

### 예상 화면 구성

상단: 라운드(3 / 10)·남은 시간 막대·칩 / 중단: 사선 시점 3D 판, 카드를 끄는 동안 반투명 말과 사거리 원 / 하단: 팩, 손패 6장, 턴 종료 버튼

## 2. 주요 기능 및 그래픽스 기술

| 기능 | 구체적인 동작/완료 기준 | 관련 그래픽스 기술 | 우선순위 |
|---|---|---|---|
| 판, 카메라 | 3D 판을 오른쪽 드래그로 돌리고 휠로 줌 | 모델링·뷰 변환(lookAt), 원근 투영, 깊이 검사 | 필수 |
| 몹 이동 | 몹이 길을 한 칸씩 뛰며 계속 돈다 | 경로 보간, 포물선 이동, 이징 | 필수 |
| 라운드·타이머 | 15초 등장, 30초 제한, 턴 종료로 다음 라운드 | 시간 기반 업데이트 | 필수 |
| 말 배치·자동 공격 | 카드를 끌어 칸에 놓으면 말이 떨어지고, 사거리 안 몹을 공격 | 마우스 광선과 평면 교차, 이징 | 필수 |
| 칩·팩·손패 | 칩으로 팩을 사면 카드가 손패로, 6장이면 구매 불가 | 게임 상태 관리 | 필수 |
| 피규어 말 | 아군 9종·적 4종 OBJ (준비 전에는 큐브) | OBJ 로딩, 텍스처 매핑 | 필수 |
| 툰 셰이딩 | 계단 명암·하이라이트·림 라이트 | 조명 모델(퐁 결과 양자화), 림 라이트 | 필수 |
| 툰 외곽선 | 말·몹 둘레에 일정한 두께의 외곽선 | 법선 방향 정점 확장 + 앞면 컬링 | 필수 |
| 파티클 | 소환 먼지, 처치 파편, 투사체, 칩이 숫자로 날아감 | 인스턴싱, 빌보드, 가산 블렌딩, 베지어 경로 | 필수 |
| 디졸브·피격 | 카드·처치된 몹이 테두리부터 빛나며 사라짐, 맞으면 번쩍임 | 노이즈 셰이더, `discard`, uniform | 필수 |
| 미리보기·사거리 | 끄는 동안 반투명 말과 맥동하는 사거리 원 | 알파 블렌딩, 시간 uniform | 필수 |
| UI·팩 개봉 | 판 위에 UI가 겹쳐 보이고, 팩을 사면 카드가 뒤집혀 손패로 | 직교 투영, 텍스처, 회전 변환 | 필수 |
| 화면 전환·데모 키 | 타이틀 → 게임 → 결과, F1~F4로 발표 중 장면 이동 | 상태 관리, 입력 처리 | 필수 |
| 운석·화면 흔들림 | 운석이 떨어져 폭발하고 화면이 흔들림 | 파티클, 뷰 행렬 흔들기 | 권장 |
| 홀로그램 카드 | 영웅 카드에 보는 각도 따라 무지개 띠 | 시선·법선 각도 셰이더 | 권장 |
| 블룸 | 발광 효과 주변으로 빛이 번짐 | 프레임버퍼 후처리, 블러 | 권장 |
| 칩 베팅·유물, 말 옮기기 | 베팅 시 몹 증가·유물 획득, 말 이동·교환 | 상태 관리, 마우스 광선 | 권장 |
| 그림자, 콘텐츠 확장 | 피규어 그림자, 주문 2종·승격·골드 부스터 | 섀도 매핑 | 선택 |

## 3. 기능별 구현 계획과 개인별 역할

| 기능/작업 | 담당 | 구현 계획 및 본인 결정 사항 | 예상 문제/검증 방법 |
|---|---|---|---|
| 엔진·카메라 | 이현수 | 직접 설계한 엔진(렌더 패스 큐, 셰이더 핫 리로드) 위에서 구면 좌표 lookAt 카메라 | 판이 뒤집힘 → 각도·거리 범위 제한, 끝값에서 확인 |
| 마우스 선택 | 이현수 | 마우스 좌표를 광선으로 바꿔 판 평면(y = 0)과 교차시켜 칸을 구함 | 칸 어긋남 → 교차점에 표시를 그려 확인 |
| 툰 렌더링·피규어 | 이현수 | 직접 만든 OBJ 로더로 크기 정규화. 조명 결과를 계단으로 양자화, 외곽선은 부풀린 메시의 뒷면만 그림 | 외곽선 모서리 벌어짐 → 부드러운 법선 모델에서 확인 |
| 파티클·디졸브 | 이현수 | 인스턴싱 빌보드(가산 블렌딩, 깊이 쓰기 끔). 디졸브는 해시 노이즈가 진행도보다 작으면 `discard` | 확인용 장면에서 키로 진행도를 바꾸며 캡처 비교, 개수별 fps |
| UI·팩 개봉 | 이현수 | 3D를 그린 뒤 직교 투영으로 UI. 숫자는 숫자 이미지 텍스처. 카드 뒤집기는 y축 회전 + 이징 | 연출 중 입력 꼬임 → 연속 구매·끌기 반복 테스트 |
| 몹 이동·라운드 | 최명준 | 길을 칸 목록으로 두고 칸 사이를 보간 + 포물선. 모든 이동은 dt 비례 | fps가 달라도 한 바퀴 시간이 같은지 측정 |
| 공격·팩·손패 | 최명준 | 사거리 안에서 가장 앞선 몹 공격. 팩은 데이터 파일의 가중치로 굴림 | 팩 1,000번 자동 개봉해 비율 확인 |
| 화면 전환·승패 | 최명준 | 타이틀·게임·결과를 상태 하나로, 타이틀·결과는 패의 카드만 바꿈 | Retry 반복 후 칩·말·이펙트 초기화 확인 |
| 로직–연출 연결 | 공동 | 로직은 `이펙트 생성(종류, 위치)`만 호출, 그리는 방법은 연출 쪽이 맡음 | 서로 기다리지 않게 각자 확인용 장면·임시 키로 개발 |

## 4. AI 활용 계획

- **사용할 AI**: Codex, Claude Code
- **원칙**: 구조와 규칙은 사람이 설계하고, AI는 반복 코드 초안·수식 예시·오류 원인 후보에 쓴다. AI가 쓴 코드도 담당자가 설명할 수 있어야 합친다.
- **정확성 확인**: 빌드·실행해 2장의 완료 기준으로 확인한 뒤 합친다.
- **틀렸을 때**: 오류 원문과 마지막 수정으로 원인을 좁히고, 이해한 뒤 직접 수정을 정한다. 반복되면 공식 문서·강의 자료로 확인한다. 요청·결과·수정 내용을 작업마다 기록한다.
- **직접 설계·구현할 부분**: 이현수 — 카메라, 마우스 광선, 파티클 구조, 툰 셰이딩·외곽선, 디졸브 / 최명준 — 게임 상태 구조(라운드·승패), 몹 경로와 한 칸 이동

| 작업 | AI 활용 계획 | 본인이 직접 판단·수정할 부분 | 결과 확인 방법 |
|---|---|---|---|
| 게임 규칙 코드 | 팩 확률·손패·칩 계산 초안 | 상태 구조를 먼저 정하고 초안을 읽고 고침 | 팩 통계, 손패 가득 참 등 경계 테스트 |
| 셰이더 수식 | 노이즈 해시, 블러 가중치 예시 | 효과 모양·파라미터 설계, 셰이더 본문 작성 | 진행도를 바꾸며 캡처 비교 |
| 오류 해결 | 셰이더·OBJ 오류 원인 후보 | 원인 확인 후 수정 여부 결정 | 컴파일·실행 결과 |
